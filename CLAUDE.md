# Trackvid-Extension — Claude Instructions

> **Orientation.** Read this header before writing code.

**What it does:** a Chrome MV3 extension that captures seller-portal sessions on
Myntra, Flipkart, AJIO, Snapdeal, Delhivery, Xbees, Meesho and Nykaa after the
operator logs in, and syncs them to TrackVid — so automations can run without
the operator re-entering a password.

|  |  |
|---|---|
| **Tier** | **1 — consumer.** A session *producer* for the automation runners. |
| **Stack** | Vite + `@crxjs/vite-plugin` · React + TypeScript · Tailwind (`clsx` + `tailwind-merge`) · lucide-react |
| **Manifest** | MV3, generated by `manifest.config.ts` — version comes from `package.json` |
| **Dev** | `npm run dev` |
| **Verify** | `npm run build` (runs `tsc -b`) |

## Layout

```
src/background/service-worker.ts   webRequest sniffing — the main capture path
src/content-scripts/ajio-page.ts   AJIO only, needs page-context reads
src/popup/                         App.tsx, screens/, components/ (BrandMark, CredentialsList,
                                   Header, StatusChip)
src/lib/                           cn.ts, types.ts
src/assets/                        icons + logos
```

## Why AJIO has a content script and the others do not

For Myntra and Flipkart, the service worker's `webRequest` sniffing is enough.
AJIO needs page-context reads — `localStorage.activeSellerProfileId` and an
in-page fetch of the work-places API for `pobIds` — which a service worker
cannot do. That asymmetry is deliberate; the reasoning is in
`manifest.config.ts`.

**Add a content script only when a platform genuinely cannot be captured from
the service worker,** and record why, next to the existing comment.

## Permissions

`cookies`, `webRequest`, `storage`, `tabs`, `notifications`. Adding a permission
widens the Chrome Web Store review and re-prompts every installed user — treat
any addition as a release decision, not an implementation detail, and say so.

## Cross-repo

| | |
|---|---|
| **Feeds** | the per-credential `<platform>Session` records that TrackVid-BE stores |
| **Consumed by** | Automated-Scripts and Trackvid-CMS, through `@trackvid/automation-core`'s session handling |
| **Platform names** | must match the registry in `TrackVid-BE/src/constants/automationRouting.ts`, **casing included** |

A session shape captured here is read by two runners in two other repos. Changing
a stored field is a cross-repo change — grep for it in Automated-Scripts,
Trackvid-CMS and TrackVid-BE before changing it.

## Do not

- **Do not invent a platform key.** A key the runners do not know produces sessions
  nothing reads, with no error anywhere.
- **Do not log, store, or transmit a marketplace password.** This extension captures
  *sessions*; passwords are gated server-side behind
  `settings.isAutoLoginOnActiveSession` and `POST /cms/credential-secret`.
- **Do not `switch` on a platform name** where a lookup table would do.
- **Do not add a permission** without flagging it as a store-review decision.
- **Do not hand-edit a generated manifest.** `manifest.config.ts` is the source.
